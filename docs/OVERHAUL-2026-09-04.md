# Tactile Orbit — engineering overhaul

## Scope

Production application: `site/`. Base commit: `c0525f7`. Working branch: `enhance/tactile-orbit`.

This is a frontend/rendering overhaul, not a manuscript rewrite or backend launch. Original cover assets, original artwork, book prose, and the high-resolution gold page solver are preserved. Historical experiments and the book minting pipeline are not repurposed.

All implementation and verification in this pass were performed by the main engineer. Subagents provided read-only audit context; the proposed implementation delegation was stopped before it changed any files.

## What changed

### Books and lighting

- Restored the production hero's missing Three.js/Troika dependencies with a reproducible vendoring script and license notices. No live CDN dependency.
- Unified cover typography with the site’s Newsreader covers; corrected centering, removed duplicate imprint lines, and explicitly culled reverse-facing cover print. Async SDF completion invalidates the scene, preventing blank titles on first load.
- Added shared cloth roughness, stronger but restrained normal relief, paper-fiber height, page-edge relief, and woven-headband bump. Original cover pixels are not recolored or regenerated.
- The inspected volume uses restrained physical sheen/clearcoat; distant ring books use cheaper standard PBR.
- Rebalanced key/fill/environment lighting to retain cover color and edge shape. Dark mode keeps a warm spotlight while retaining readable form.
- Replaced stale baked-shadow sampling with soft, moving analytic contact footprints, including a held-book shadow. These are efficient approximations, not ray-traced shadows.

### Motion and interaction

- Exponential inertia is analytically integrated in seconds, rather than adding per-frame displacement. Pointer velocity uses event timestamps. Release after a pause/cancel does not fling the book.
- Departing and arriving books share a continuous browse transition; the departing book no longer snaps closed before the ring moves.
- Hover moves the book vertically. High-frequency pointer hover hits are coalesced to one scene frame.
- Press/release intent distinguishes selecting a book from dragging/swiping/scrolling.
- Added explicit explore, cover, previous/next-page, reset-view and opt-in autoplay controls. Arrow keys turn pages when the book is open; Escape returns focus to Explore.
- Embedded vertical wheel events no longer trap ordinary page scrolling. Horizontal/Shift-wheel browsing and wheel delta-mode normalization remain available. Browser pinch zoom is not hijacked.
- Mobile cameras and compact reading controls reserve usable space for the book. Reading mode collapses the large metadata panel so it cannot cover the spread.
- Added English, Danish and Arabic labels for the new orbit controls.

### Performance and resilience

- Instanced opaque rigid ring parts by compatible geometry/material, retaining original picking proxies and live SDF text. The book geometry itself is not remeshed.
- Desktop uses 36 slots; phones use 24, retaining the ten-title catalog. Only exposed reader sheets rasterize; leaf tessellation remains 132 × 52.
- Separate display-sized ring covers and full-detail reader covers; shared cached textures are no longer disposed by an individual book.
- Reused the UV1 cloth normal and cached spine typography. Same-book rebinding skips atlas/print rebuilding; SDF paper atlases are retained across content changes.
- Headbands deform their existing geometry buffers instead of repeatedly creating/discarding TubeGeometry. Spine arc workspace is reused.
- Fixed page-11 print accumulation and released old page-deformation textures, SDF meshes and materials on rebind. Typesetting diagnostics are bounded and settled promises are removed.
- Reader preparation is serialized to avoid racing a background warm-up against a selection.
- Fully demand-driven scene scheduling: no perpetual scene rAF while idle, no GPU render while idle, and work pauses when the embed is off-screen or its context is lost.
- The React shelf retains real linked covers until the iframe confirms readiness. Script failure, no WebGL, data-saver mode and reduced motion keep a readable static shelf. Lost WebGL contexts can recover; messages are checked against both origin and iframe source.

### Wider website/tooling

- Responsive WebP variants and intrinsic dimensions for all 36 source cover/painting images, with original-format picture fallback and meaningful sizes.
- Keyboard-complete language menu, Escape/focus restoration for the mobile menu, and honest unavailable-format presentation instead of inert download/listen anchors.
- Fixed the local production server's project path, HTML/WebP/font MIME types, static path containment, and request body forwarding.
- Typechecking now generates the route tree first, so it works on a fresh checkout.
- Patched the transitive nanoid dependency from 3.3.17 to the advisory-fixed release; the final full npm audit reports no vulnerabilities.
- Added unit tests, production-build Chromium tests, pinned tooling, and a GitHub Actions quality workflow. The workflow has not run on GitHub until the branch is pushed.

## Verification

- `npm audit --audit-level=high`: passes; zero reported vulnerabilities at verification time (nanoid 3.3.18).
- `npm run test`: 5 deterministic math/input/ring tests pass.
- `npm run typecheck`: passes, including fresh route generation.
- `npm run build`: client and SSR production builds pass.
- 10 browser scenarios cover:
  1. Boot, visible titles, browsing, instanced canvas picking, idle scheduling and no external network.
  2. Cover opening, all five forward pages, backward page, unchanged headband geometry, idle reader and reopen.
  3. Phone orbit/inspect/read, orientation change, no horizontal overflow, and reverse-title culling.
  4. Dark scene and inspected-book rendering.
  5. Real production-homepage enhancement plus deliberately blocked module fallback.
  6. Reduced motion, Arabic RTL, responsive imagery and server-rendered chapter/hreflang output.
  7. Simulated WebGL loss and restoration without reloading.
  8. Language-menu arrows, Home/End and Escape focus restoration.
  9. Mobile menu focus and unavailable-format honesty.
  10. Explicitly unavailable WebGL with real linked shelf fallback.

The browser scenarios were run in bounded groups because the execution environment limits individual shell calls to two minutes. Some early full-suite attempts hit that runner limit; tests were rerun individually/in groups rather than treating interrupted runs as passes. Screenshot review caught and corrected a mobile reverse-cover-print issue that the initial functional assertions missed.

Evidence is in `docs/qa/`. The tests generate those screenshots from the production build. No existing production artwork was changed to create them.

## Running and maintaining

From `site/`:

```sh
npm ci
npm run check
npm run test:e2e
npm run serve
```

The review server is at `http://localhost:3100/en`; standalone scene: `/orbit/index.html`.

`npm run images` regenerates derivatives and the image manifest. `npm run vendor:orbit` reconstructs ignored vendor files from the lockfile-pinned dependencies. Build/dev invoke vendoring automatically. On macOS/Windows, install Playwright's Chromium (`npx playwright install chromium`) or supply `PLAYWRIGHT_CHROMIUM_EXECUTABLE`; Linux uses the npm-packaged test browser by default.

See `site/public/orbit/README.md` for module ownership and rendering lifecycle rules.

## Remaining release work

- The existing website still contains prototype catalog statistics, sample chapters and mocked feedback/request/vote/experience persistence. Connect the documented backend contracts—or disable/clearly label those forms—before a public launch. This pass does not present those services as implemented.
- The 3D page sequence remains presentation/sample content. The SSR reader is the accessible reading destination; publishing full manuscripts is separate work.
- Recheck touch/pinch behavior, text legibility, thermal behavior and frame pacing on real low-end mobile devices, Safari and high-DPR hardware. No synthetic resource count substitutes for that pass.
- Review design direction before publishing. No remote branch, pull request, merge or production deployment is implied by local verification.
